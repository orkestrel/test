**Findings**

- **Medium — The published example does not compile.** At [helpers.ts:129](/C:/Users/mikes/WebstormProjects/test/src/browser/helpers.ts:129), `link.contains(hit)` passes `Element | undefined` to the installed DOM signature `contains(other: Node | null)`. Compiling the extracted example in memory with the repository’s compiler options produced **TS2345**. Changing the expression to `hit !== undefined && link.contains(hit)` produced no diagnostics. Correct the example and the accompanying unguarded recommendation; the return signature itself can remain unchanged.

- **Medium — The driver explanation is false for the installed provider.** [The remarks](/C:/Users/mikes/WebstormProjects/test/src/browser/helpers.ts:112) say a driver clicks the element’s bounding-box centre. The installed Playwright implementation instead clips content quads to the viewport and selects a point in the first surviving quad; see [coreBundle.js:20084](/C:/Users/mikes/WebstormProjects/test/node_modules/playwright-core/lib/coreBundle.js:20084). Vitest’s provider delegates to the locator’s `click` method. A wrapped element’s union-box centre can therefore miss while the driver selects a painted fragment. Document this helper as a measurement of the specified point, without claiming it predicts the driver’s chosen click point.

- **Medium — The reachability guidance omits conditions that change its interpretation.** Shadow retargeting, absent layout, and a partially visible element with an off-screen centre invalidate the suggested general `contains` ruling. The following hazard rulings specify the required boundaries.

**Hazard rulings**

- **Viewport-relative coordinates — real documentation defect, Medium.** A rendered element whose centre is outside its document’s viewport returns `undefined`; the helper does not scroll. The TSDoc explicitly documents this and links `isOutsideViewport`, although the guide row does not explain the composition. The link is insufficient: `isOutsideViewport` tests whether the *whole rectangle* misses the viewport. For `left = -80` and `width = 100`, the right edge is `20`, so that predicate returns false, while the centre is `-30` and `readHit` returns `undefined`. Also, the predicate uses global `window`, whereas `readHit` uses the owner document. State these limits and distinguish centre location from whole-rectangle intersection. `undefined` does not prove coverage. The browser’s viewport rejection is specified by [CSSOM View](https://drafts.csswg.org/cssom-view/#dom-document-elementfrompoint).

- **Shadow DOM — real undocumented limitation, Medium.** For an element inside a shadow tree, document-level hit testing can return its host. The inner element does not contain that host, so the documented ruling reports a miss even when the pointer reaches the inner element. Neither the remarks nor the cases name this boundary. Preserve document-level semantics only with an explicit limitation and a real shadow fixture; do not silently reinterpret the function as a deepest-shadow-node reader. The retargeting behavior is exercised by the [Web Platform Tests](https://raw.githubusercontent.com/web-platform-tests/wpt/master/shadow-dom/DocumentOrShadowRoot-prototype-elementFromPoint.html).

- **Zero-area element — real undocumented edge case, Medium.** Zero width leaves the tested x-coordinate at `left`; zero height leaves y at `top`. The helper still hit-tests that coordinate and may return another element. An element with no layout boxes has a zero rectangle at the origin, so this can return the root or another element at `(0, 0)`, rather than `undefined`. These cases are absent from the added tests. Document that the reader does not validate layout and cover zero-area and absent-layout inputs. The rectangle rules are specified by [CSSOM View](https://drafts.csswg.org/cssom-view/#dom-element-getboundingclientrect).

- **Subpixel geometry — no demonstrated implementation defect.** The helper introduces no rounding and passes fractional coordinates through unchanged. A point exactly on a boundary remains subject to browser hit-testing precision; adding rounding would change the requested measurement. The wrap fixture has sensible horizontal slack, but its generic font does not prove universal vertical metrics. Its fragment and gap assertions fail visibly if those assumptions stop holding. No actual font-related flake was established.

- **Return type versus predicates — retain the signature, clarify its limits.** `Element | undefined` is appropriate for a reader that identifies the hit node. A boolean would discard useful evidence. The return alone cannot distinguish missing layout from an unrelated hit at the resulting coordinate, and `undefined` does not identify why hit testing failed. Callers needing those distinctions must separately inspect rendering and geometry. Do not add a speculative result union or convert this reader into a predicate. Correct the guarded example and document the separate obligations.

- **Escaped union arm — escaping is correct; signature parity is not enforced.** The Markdown parser unescapes `\|`, but `findDrift` does **not compare the Types cell**. In-memory checks showed: the original row has no drift; removing the escape shifts `undefined` into the Summary cell and produces drift; replacing the return type with `boolean` leaves the comparison green. Thus removing the escape does not fail silently, but an incorrect signature can. This is an existing parity limitation, **Low severity**, not a defect in the row’s escaping.
